# CLI Selector and Artifact Discovery Overhaul

## Goal

Make non-TUI commands predictable for humans and agents by removing ambiguous positional arguments, using the same explicit selectors everywhere, and adding a first-class way to find artifact paths without opening the web UI or dumping large logs.

The current CLI has two core problems:

1. Positional arguments are overloaded. `localci status noisy-fail` looks like a task query, but it is parsed as a commit.
2. Artifact locations are available, but only as a side effect of task detail, web navigation, or TUI navigation.

## Design Principles

- No command should require positional arguments for repo, commit, or task selection.
- Every selector should be a named flag: `--repo`, `--commit`, `--task`, and where needed `--attempt`.
- Omitted selectors should have useful defaults.
- Commands should print bounded summaries by default. Full logs belong in web/TUI or explicit file access.
- Human output should be readable and copyable. Machine output should use `--json`.
- Short task names should work where unambiguous. `--task noisy-fail` should match `//:localci:noisy-fail`.
- Full task names should always work.
- Ambiguous short task names should fail with candidates.

## Shared Selector Semantics

All selector-aware commands should share one parser for common selectors. Selector-aware commands are `invoke`, `postcommit`, `status`, `history`, `artifacts`, `wait`, `cancel`, `web`, and `dash`. Lifecycle/config commands such as `start`, `restart`, `stop`, `daemon run`, and `install-hooks` do not take task/run selectors.

```text
--repo DIR       Repository to query or run. Defaults to the nearest ancestor of cwd containing .git.
--commit REF     Commit/run label to query. Defaults depend on command.
--task TASK      Task name or unambiguous short task name.
--attempt N      Task attempt. Defaults to the selected task's latest attempt.
--no-clone       Use or query the live working-tree run label, e.g. <commit>*.
--json           Print JSON.
```

Commit resolution:

- `--commit HEAD` resolves to the repo's current HEAD commit.
- `--commit HEAD*` resolves to the current working-tree run label.
- Any other `--commit` value is treated as a LocalCI run label exactly as stored.
- If `--no-clone` is passed and `--commit` is omitted, use `HEAD*`.
- If `--no-clone` is passed and `--commit` is present, append `*` unless already present.

Task resolution:

- Match exact task name first.
- If no exact match, match short task names generated by the same logic as the UI.
- If one short match exists, use it.
- If multiple short matches exist, fail with all matching full task names.
- If no task matches, fail with a helpful error and suggest `localci history --task <name>` when the user might be looking across commits.

Default repo:

- For repo-scoped commands, default to the nearest ancestor of cwd with `.git` as a file or directory.
- If no repo is discoverable, fail with: `could not find a Git repo from cwd; pass --repo <path>`.

Default commit:

- `invoke`: current HEAD, because it creates a new run.
- `postcommit`: current HEAD when omitted, but hooks should pass `--commit`.
- `status`, `wait`, `artifacts`, `web`: latest known LocalCI run for the selected repo.
- `history`: no single commit; it lists recent runs.
- `cancel`: no commit means cancel the active task. Selectors can narrow cancellation.

Default task:

- Query commands default to all tasks in scope.
- Run-producing commands default to all discovered LocalCI tasks.
- `cancel` with no selectors defaults to the active task.

## New Command: `localci artifacts`

Purpose: print filesystem paths for artifacts without printing log contents.

Default behavior:

```sh
localci artifacts
```

Prints all artifacts for all tasks in the latest run for the current repo.

Examples:

```sh
localci artifacts --task noisy-fail
localci artifacts --commit 6bd8d389f3f550da3fccb11bac380d59268fe320 --task //:localci:noisy-fail
localci artifacts --failed --primary
localci artifacts --task noisy-fail --primary --paths-only
localci artifacts --json --failed
```

Flags:

```text
--repo DIR       Repository to query.
--commit REF     Commit/run label to query. Defaults to latest run.
--task TASK      Task name or unambiguous short task name. Defaults to all tasks.
--attempt N      Attempt to query. Defaults to latest attempt for each selected task.
--failed         Only include failed or timed-out tasks.
--primary        Only include each task's primary artifact, normally combined.log.
--paths-only     Print only artifact paths, one per line.
--json           Print structured JSON.
```

Human output:

```text
Artifacts
repo    /Users/steve/dev/cli/localci
commit  6bd8d389f3f550da3fccb11bac380d59268fe320

status  task        attempt  artifact      path
failed  noisy-fail  1        combined.log  /Users/steve/.localci/.../combined.log
ok      build       1        combined.log  /Users/steve/.localci/.../combined.log
ok      build       1        bin/localci   /Users/steve/.localci/.../bin/localci
```

JSON output:

```json
{
  "repo": "/Users/steve/dev/cli/localci",
  "commit": "6bd8d389f3f550da3fccb11bac380d59268fe320",
  "artifacts": [
    {
      "task": "//:localci:noisy-fail",
      "short_task": "noisy-fail",
      "status": "failed",
      "attempt": 1,
      "artifact": "combined.log",
      "path": "/Users/steve/.localci/.../combined.log",
      "primary": true
    }
  ]
}
```

## New Command: `localci history`

Purpose: answer questions across runs, especially “show me the most recent noisy-fail tasks in this repo across commits.”

Default behavior:

```sh
localci history
```

Prints recent runs for the current repo, newest first.

Examples:

```sh
localci history --task noisy-fail
localci history --failed
localci history --task noisy-fail --limit 20
localci history --repo ~/dev/cli/localci --json
```

Flags:

```text
--repo DIR       Repository to query. Defaults to current repo.
--commit REF     Optional exact run label to include.
--task TASK      Task name or unambiguous short task name.
--status STATUS  Filter tasks/runs by status: ok, failed, timed-out, running, queued, not-run.
--failed         Shortcut for --status failed --status timed-out.
--limit N        Maximum rows. Defaults to 20.
--json           Print structured JSON.
```

`--status` may be repeated. `--failed` is equivalent to `--status failed --status timed-out`.

Human output without `--task`:

```text
History
repo  /Users/steve/dev/cli/localci

commit        branch  summary                 updated
6bd8d389f3f5  main    11 ok, 1 failed         3m ago
77883f755d11  main    11 ok, 1 failed         7m ago
4c250037839a  main    10 ok, 2 failed         11m ago
```

Human output with `--task noisy-fail`:

```text
History
repo  /Users/steve/dev/cli/localci
task  noisy-fail

commit        status  attempt  duration  failure  updated
6bd8d389f3f5  failed  1        72ms      exit     3m ago
77883f755d11  failed  1        51ms      exit     7m ago
4c250037839a  failed  1        49ms      exit     11m ago
```

## Existing Command Changes

### `localci status`

New purpose: bounded status summary for one run, optionally narrowed to one task. It never prints full log contents.

Usage:

```text
localci status [--repo DIR] [--commit REF] [--task TASK] [--attempt N] [--no-clone] [--json]
```

Defaults:

- `--repo`: current repo.
- `--commit`: latest LocalCI run for the repo.
- `--task`: all tasks.
- `--attempt`: latest attempt.

Human output with all tasks:

```text
Status
repo     /Users/steve/dev/cli/localci
commit   6bd8d389f3f550da3fccb11bac380d59268fe320
summary  11 passed, 1 failed, 0 timed out, 0 not run
branch   main

status  task             attempt  duration  failure
ok      build            1        6.5s      -
failed  noisy-fail       1        72ms      exit
ok      //web:test       1        1.9s      -
```

Human output with `--task noisy-fail`:

```text
Task
repo     /Users/steve/dev/cli/localci
commit   6bd8d389f3f550da3fccb11bac380d59268fe320
task     //:localci:noisy-fail

status   failed
attempt  1
duration 72ms
failure  exit
output   /Users/steve/.localci/.../attempt-001

artifacts:
  combined.log  /Users/steve/.localci/.../combined.log
```

No primary log content is printed. If users want the log:

```sh
cat "$(localci artifacts --task noisy-fail --primary --paths-only)"
```

### `localci wait`

New purpose: wait for a run to complete and print bounded summary plus artifact path hints for failures.

Usage:

```text
localci wait [--repo DIR] [--commit REF] [--task TASK] [--no-clone] [--json]
```

Defaults:

- `--repo`: current repo.
- `--commit`: latest LocalCI run for the repo.
- `--task`: all tasks.

Behavior:

- Exit nonzero if any selected task fails or times out.
- Never dump full log contents.
- For failures, print primary artifact paths and result URLs.

Failure output:

```text
Completed
repo     /Users/steve/dev/cli/localci
commit   6bd8d389f3f550da3fccb11bac380d59268fe320
summary  11 passed, 1 failed, 0 timed out, 0 not run

failed tasks:
status  task        attempt  duration  failure  primary artifact
failed  noisy-fail  1        72ms      exit     /Users/steve/.localci/.../combined.log

results:
  noisy-fail  http://127.0.0.1:61924/repo/cli/localci/commit/...
```

### `localci invoke`

New purpose: run an ad hoc check for a commit or the working tree. This is useful for manual testing, but it is not the primary workflow; the normal path is still `postcommit` from the Git hook plus `wait`, `status`, `history`, and `artifacts` for inspection.

Usage:

```text
localci invoke [--repo DIR] [--commit REF] [--task TASK] [--wait] [--no-clone] [--annotation KEY=VALUE] [--json]
```

Defaults:

- `--repo`: current repo.
- `--commit`: `HEAD`.
- `--task`: all discovered LocalCI tasks.
- `--no-clone`: when present, run against the live working tree and label the run as `<commit>*`.

`--task` must filter before enqueueing/running. It is not acceptable to enqueue all tasks and hide the others in output.

### `localci postcommit`

New purpose: hook entry point, but still usable manually.

Usage:

```text
localci postcommit [--repo DIR] [--commit REF] [--task TASK] [--annotation KEY=VALUE] [--json]
```

Defaults:

- `--repo`: current repo.
- `--commit`: `HEAD`.
- `--task`: all discovered LocalCI tasks.

Hook command installed by `install-hooks`:

```sh
localci postcommit --repo "$repo" --commit "$commit"
```

### `localci cancel`

New purpose: cancel active or queued tasks.

Usage:

```text
localci cancel [--repo DIR] [--commit REF] [--task TASK] [--no-clone] [--json]
```

Defaults:

- No selectors: cancel the active task.
- `--repo` only: cancel the active task for that repo if one exists.
- `--repo --commit`: cancel all active/pending tasks for that run.
- `--repo --commit --task`: cancel matching task(s) for that run.
- `--task` without `--commit`: cancel active/pending tasks with that task name in the selected repo, newest first.

Safety:

- Print exactly what was canceled.
- If multiple queued tasks match, cancel all matches and report count.

### `localci web`

New purpose: open the web UI to the most specific selected page.

Usage:

```text
localci web [--repo DIR] [--commit REF] [--task TASK] [--attempt N] [--artifact ARTIFACT] [--no-clone]
```

Defaults:

- `--repo`: current repo.
- `--commit`: latest run.
- `--task`: repo/commit page if omitted.
- `--attempt`: latest task attempt.
- `--artifact`: task page if omitted, artifact page if present.

### `localci install-hooks`

Usage:

```text
localci install-hooks [--repo DIR]
```

Behavior:

- Defaults to current repo.
- Installs a hook that calls `localci postcommit --repo "$repo" --commit "$commit"`.

### Daemon commands

Daemon lifecycle commands do not use selectors.

```text
localci start
localci restart
localci stop
localci daemon run
```

## Data Model and Implementation Notes

### Shared selector type

Add a shared selector type in `internal/cli`:

```go
type cliSelector struct {
    RepoArg  string
    RepoDir  string
    Commit   string
    Task     string
    Attempt  int
    NoClone  bool
}
```

Then add helpers:

- `parseSelectorFlags(args, allowedFlags)`.
- `resolveRepoSelector`.
- `resolveCommitSelector(defaultMode)`.
- `resolveTaskSelector(tasks, selector.Task)`.
- `selectedTaskStatuses(view, selector)`.
- `selectedTasksForEnqueue(discovered, selector.Task)`.

The important change is that parsing should happen once and be reused, instead of each command hand-parsing positional arguments.

### Artifact command implementation

Use `BuildCommitStatusView` for a selected commit, then walk selected tasks and their selected attempts.

For each selected task:

- Use latest attempt by default.
- Use `applySelectedAttempt` when `--attempt` is set.
- Use `PrimaryArtifact(task)` for `--primary`.
- Otherwise use `task.Artifacts`.

### History command implementation

Use `HistoryReader.ListRepoCommits(repoDir)` and summarize run records. For task filtering, build or derive task status rows from each run:

- Prefer `RunRecord.DiscoveredTasks` plus `TaskResults`.
- Avoid running task discovery against live checkout for old commits.
- For old runs with missing discovered task data, fall back to task records only.

This makes history stable and cheap.

### Task-filtered enqueue implementation

Add task filtering to the queue path, not just CLI output:

- Extend `InvokeRequest` or equivalent daemon request data with selected task names.
- Extend `Postcommit` request handling with selected task names.
- Resolve short task names after discovery and before queue entries are written.
- Store the discovered task list for the run as the selected task list when a filtered run is requested.

This keeps `invoke --task test`, `postcommit --task test`, `status`, `wait`, and web/TUI views internally consistent.

### Remove log dumping from non-TUI CLI

Change `printTaskDetail` and `printWaitSummary`:

- Keep output directories and artifact paths.
- Remove `LoadPrimaryLog` content printing.
- Keep primary artifact display name and path.
- Point users to `localci web`, `localci dash`, or `cat "$(localci artifacts --primary ...)"` style workflows.

Do not add a `localci logs` command yet. It is tempting, but it reintroduces unbounded output unless carefully paged or tailed. Web/TUI already solve log viewing.

## Migration and Compatibility

Because this is prerelease software, we can remove positional parsing instead of preserving it.

Breaking changes:

- `localci postcommit <commit>` becomes `localci postcommit --commit <commit>`.
- `localci postcommit --task <task>` becomes valid and queues only matching task(s).
- `localci status <commit> [task]` becomes `localci status --commit <commit> [--task TASK]`.
- `localci wait [commit]` becomes `localci wait [--commit REF]`.
- `localci web [commit] [task]` becomes `localci web [--commit REF] [--task TASK]`.
- `localci cancel <commit> <task>` becomes `localci cancel --commit <commit> --task <task>`.

The installed Git hook must be updated at the same time.

## Implementation Order

1. Add shared selector parsing and tests.
2. Add task-filtered enqueue support in runner/daemon data paths.
3. Convert `status` to explicit flags and remove log dumping.
4. Add `artifacts` with human and JSON output.
5. Add `history` with task/status filtering.
6. Convert `wait`, `web`, and `dash` to explicit selectors.
7. Convert `postcommit`, `invoke`, and `cancel`.
8. Update top-level and per-command help text.
9. Update docs.
10. Run `mise run check`, web tests if UI links changed, and a daemon-backed smoke test:

   ```sh
   localci status
   localci artifacts --failed --primary
   localci history --task noisy-fail
   localci invoke --no-clone --task fmt --wait
   ```

## Consistency Pass Notes

After rereading the design, these are the consistency decisions to keep:

- `status` remains run-focused; `history` is the cross-commit query command.
- `artifacts` is run-focused by default; use `history --task` first when searching across commits.
- `--task` on `invoke` and `postcommit` must enqueue only selected tasks. No output-only filtering.
- `wait --task` is useful and bounded, but it should wait for the selected task within a selected run, not search across history.
- `cancel --task` without `--commit` can reasonably operate across active/pending queue entries because cancellation is about current queue state, not historical runs.
- `postcommit --commit` should be optional for manual ergonomics, but hooks should always pass it explicitly.
- Non-TUI commands should never print full logs by default.
